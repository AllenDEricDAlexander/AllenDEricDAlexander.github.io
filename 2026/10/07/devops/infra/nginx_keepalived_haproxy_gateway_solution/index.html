裸金属 Nginx + Keepalived + HAProxy 企业级网关方案

1. 背景与目标

本方案用于在裸金属主机上部署一套企业级 Web 网关，适用于前后端分离系统。

核心目标如下：

  • 使用 Nginx 提供前端静态资源访问；
  • 前端直接访问网关地址；
  • 后端接口统一通过 /api 路径区分；
  • 使用 HAProxy 管理后端 API 服务节点池；
  • 使用 Keepalived + VIP 实现网关入口高可用；
  • 支持前端运行时动态配置；
  • 支持后端节点动态维护；
  • 支持 Nginx / HAProxy / Keepalived 配置导出，方便迁移；
  • 支持部署、发布、回滚、校验、重载的脚本化；
  • 支持企业级日志、监控、安全和运维标准化。

2. 总体架构

推荐部署两台网关节点：

节点 角色 部署组件
gateway-01 MASTER Nginx + HAProxy + Keepalived
gateway-02 BACKUP Nginx + HAProxy + Keepalived

两台机器保持配置一致，VIP 只绑定在当前 MASTER 节点上。当 MASTER 异常时，VIP 自动漂移到 BACKUP 节点。

3. 组件职责划分

3.1 Nginx 职责

Nginx 负责 Web 入口层能力，包括：

  • 监听 80 / 443；
  • 提供前端静态资源；
  • 支持 React / Vue / Angular 等 SPA 路由刷新；
  • 将 /api 请求统一转发到 HAProxy；
  • 处理 gzip / brotli 压缩；
  • 处理静态资源缓存；
  • 处理 HTTPS 证书；
  • 输出访问日志和错误日志；
  • 处理限流、Header 透传、跨域策略；
  • 支持配置校验和 reload。

Nginx 在本方案中不直接管理复杂的后端节点池，避免职责过重。

3.2 HAProxy 职责

HAProxy 负责 API 后端池，包括：

  • API 后端负载均衡；
  • 后端服务健康检查；
  • 后端节点上下线；
  • 后端节点摘流；
  • 后端节点权重调整；
  • 连接超时、请求超时、响应超时控制；
  • API 层访问日志；
  • 后端池动态维护。

HAProxy 是后端服务流量治理的核心，不建议让 Nginx 同时承担复杂后端池维护职责。

3.3 Keepalived 职责

Keepalived 只负责网关入口高可用：

  • VIP 漂移；
  • MASTER / BACKUP 切换；
  • 网关节点健康检查；
  • Nginx / HAProxy 异常时降权；
  • 当前 MASTER 节点异常时释放 VIP。

Keepalived 不做业务负载均衡，只负责 VIP 高可用。

5.3 健康检查内容

Keepalived 的健康检查建议覆盖：

  • Nginx 进程是否存活；
  • Nginx 端口是否监听；
  • Nginx 本地健康检查是否成功；
  • HAProxy 进程是否存活；
  • HAProxy API 代理端口是否监听；
  • HAProxy 后端池是否至少存在一个可用节点；
  • 磁盘空间是否充足；
  • 系统负载是否异常。

健康检查不要过度激进，避免因为短时间抖动导致 VIP 频繁漂移。

10.1 导出内容

10.2 不建议直接导出的内容

以下内容建议谨慎处理：

  • TLS 私钥；
  • 内部账号密码；
  • HAProxy stats 密码；
  • Runtime API socket 敏感权限；

如果必须导出，需要加密保存，并限制权限。

10.3 迁移流程

迁移时必须重点检查：

  • 网卡名称是否一致；
  • VIP 是否属于当前网段；
  • 防火墙是否允许 80、443、VRRP；
  • 后端服务 IP 是否在新环境可达；
  • 证书路径是否正确；
  • DNS 是否需要调整。

14. 安全设计

14.1 Nginx 安全

建议：

  • 只开放 80 / 443；
  • HTTP 自动跳转 HTTPS；
  • 配置 TLS；
  • 禁止访问 .git、.env、备份文件等敏感路径；
  • 配置安全响应头；
  • 限制上传大小；
  • 设置合理的请求超时；
  • 对 /api 设置必要限流；
  • CORS 不要直接使用全量 *；
  • 静态资源设置合理缓存策略。

14.2 HAProxy 安全

建议：

  • HAProxy API 代理端口只监听本机或内网；
  • stats 页面必须加认证；
  • Runtime Socket 限制权限；
  • 后端服务只允许网关机访问；
  • 健康检查接口不要返回敏感信息。

14.3 Keepalived 安全

建议：

  • 固定 VRRP 网卡；
  • 明确 VIP 所在网段；
  • 防火墙允许 VRRP；
  • 主备节点时间同步；
  • 健康检查脚本权限收紧；
  • 避免频繁漂移；
  • 避免主备双主。

15. 故障处理设计

故障场景 处理方式
Nginx 进程异常 Keepalived 降权，VIP 漂移
HAProxy 进程异常 Keepalived 降权，VIP 漂移
单个 API 节点异常 HAProxy 健康检查摘除节点
gateway-01 宕机 gateway-02 接管 VIP
前端发布失败 回滚到上一个 release
配置渲染失败 保留旧配置，不 reload
Nginx 配置校验失败 阻止 reload
HAProxy 配置校验失败 阻止 reload
VIP 频繁漂移 检查 healthcheck、网络抖动、系统负载
后端全部不可用 HAProxy 返回错误页或统一 503

16.3 前端灰度

裸金属 Nginx 前端灰度可以按以下方式实现：

  • 基于不同域名灰度；
  • 基于 Cookie 灰度；
  • 基于 Header 灰度；
  • 基于 IP 白名单灰度；
  • 使用独立灰度 release 目录。

如果前端灰度需求复杂，建议后续引入统一网关或 Ingress 层能力，不要在 Nginx 配置里堆太多业务规则。

20. 总结

本方案适合企业在裸金属环境下建设前后端分离网关。

设计重点不是单纯把 Nginx、HAProxy、Keepalived 装起来，而是把以下能力标准化：

  • 网关入口高可用；
  • 前端资源版本化发布；
  • 后端服务节点池治理；
  • 配置模板化与动态化；
  • 配置导出与迁移；
  • 校验、重载、回滚流程；
  • 日志、监控、安全和告警。

最终形成一套可部署、可迁移、可回滚、可排障、可扩展的企业级裸金属 Web 网关方案。
