Spring Boot 配置体系详解：YAML、加载顺序、Profile、属性注入与 Maven POM 整合

在 Spring Boot 项目中，配置看似只是一个 application.yml，实际却牵涉三件不同的事：配置文件从哪里被发现、同一个配置项由谁覆盖，以及最终如何注入 Java 对象。如果再引入 Maven 的 pom.xml 和多环境构建，很容易把 Maven Profile、Spring Profile、资源过滤和运行时参数混在一起。

本文以 Spring Boot 3.5.x + Java 21 + Maven 为例，从工程结构出发，将这些机制串起来，并给出能够直接套用的配置和代码。Spring Boot 2.3 及更早版本的配置文件加载机制与本文讨论的 Spring Boot 2.4+ Config Data 机制不同，阅读老教程时尤其要注意。

1. 先理解配置体系的三个层次

这张图最需要记住的是：

层次 处理的问题 典型配置或命令 发生时间
Maven 构建 依赖版本、构建插件、替换构建常量 pom.xml、mvn -Pprod package、@project.version@ 打包时
Spring Boot 配置发现 找哪些配置文件、按什么位置加载 application.yml、spring.config.* 应用启动早期
Spring Profile 哪些环境配置生效 application-dev.yml、--spring.profiles.active=dev 应用启动时
属性源覆盖 多个来源定义同一 Key 时谁获胜 环境变量、-D、--app.name= 配置解析时
配置值注入 将最终值提供给业务代码 @Value、@ConfigurationProperties Bean 创建与绑定时

Maven 的 -Pprod 与 Spring Boot 的 --spring.profiles.active=prod 没有自动关联关系。 两者名称相同，也不会天然触发对方。这是多环境项目最常见的误区之一。

建议先采用“单一可执行包 + 多环境运行时配置”的方式组织工程，而不是为 dev、test、prod 各编译一套完全不同的应用。

3.5.2 激活 Profile 的方式

方式 示例 适用场景
命令行参数 java -jar app.jar --spring.profiles.active=prod 直接运行 JAR

3.6 所有配置文件按以下顺序考虑：优先级从低到高

这一小节只讨论 Config Data 文件之间的优先级，暂时不加入命令行、环境变量、@TestPropertySource 等其它属性源。

Spring Boot 官方将常见的配置文件覆盖顺序归纳为以下四层：

优先级（低 → 高） 配置文件来源 示例
1 JAR 内的普通配置 classpath:/application.yml
2 JAR 内的 Profile 专属配置 classpath:/application-prod.yml
3 JAR 外的普通配置 file:./application.yml
4 JAR 外的 Profile 专属配置 file:./application-prod.yml

这里最容易产生误解的是：外部普通配置的优先级可以高于 JAR 内的 Profile 专属配置。 不应该把所有 application-prod.yml 一概理解为高于所有 application.yml。

例如启动 prod 时存在：

文件 app.name 是否生效
JAR 内 application.yml jar-base 被覆盖
JAR 内 application-prod.yml jar-prod 被覆盖
外部 ./application.yml external-base 被覆盖
外部 ./application-prod.yml external-prod 最终生效

如果删除外部的 application-prod.yml，上述示例中最终将变成 external-base，而不是 jar-prod。

再补充三个限制条件：

  1. 同一位置、同一名称同时有 .properties 和 YAML 格式时，.properties 优先。
  2. 同一位置组中多个活动 Profile 遵循后者覆盖前者。 如果显式拆分了不同 location group，需要按照各组的处理顺序判断。
  3. spring.config.import 和自定义 spring.config.location 会改变简单的默认覆盖链。 不要把上面的四层表当成适用于所有自定义配置结构的绝对全序。

还要区分集合类型的覆盖规则。在 @ConfigurationProperties 绑定时：

最终绑定到 List<String> 的是 [node-c]，不是 [node-a, node-b, node-c]。对于 Map/对象，则可以根据 Key 进行属性级合并和覆盖；具体行为仍取决于绑定目标类型。

4. 配置文件值注入

Spring Boot 常用的读取方式有三种：

方式 适合场景 特点
@Value 少量简单属性 使用方便，支持 ${...} 和 SpEL
Environment 运行时查询属性、调试 可以按需访问，也能读取激活的 Profile

4.1 配置文件占位符

这里一定要区分Spring 运行时占位符与Maven 构建期占位符。

语法 处理阶段 示例 谁来处理
${name} Spring 运行时 ${DB_HOST:localhost} Spring Environment
${name:default} Spring 运行时 ${APP_TIMEOUT:5s} Spring 属性解析器
${random.uuid} Spring 运行时 ${random.uuid} Spring Boot 的随机属性源
@project.version@ Maven 构建期 @project.version@ Maven Resource Filtering
@deploy.target@ Maven 构建期 @deploy.target@ Maven Resource Filtering

Spring 占位符：

解释如下：

  • ${APP_NAME:order-service}：优先读取 APP_NAME，否则使用默认值 order-service。
  • ${APP_TIMEOUT:5s}：默认值为 5s，绑定到 Duration 后可直接操作时间类型。
  • ${random.uuid}：获取随机 UUID，适合非持久化的临时标识；不要用它替代稳定业务 ID。
  • ${DB_PASSWORD:}：允许默认空串，但生产数据库等关键凭据应配合强制校验或启动失败策略，不要默默使用空密码。

属性之间也可以互相引用：

推荐在 Spring 占位符中使用规范的短横线形式（canonical kebab-case），例如 ${app.read-timeout}，以便享受更一致的宽松查找规则。

Maven 占位符：

打包时 Maven 将其替换为 POM 中的值，例如 1.0.0、springboot-config-demo、local。当资源过滤未开启或者该文件未被过滤时，它们只会作为普通字符串留在最终 JAR 中，Spring Boot 不会自动解释 @project.version@。

不建议把 Maven 资源过滤的定界符改回 ${...}。因为 Maven 和 Spring 都使用这套语法时，可能在构建阶段误处理原本应该保留到运行时的 ${DB_HOST} 等配置。

5. Spring Boot 配置与 Maven pom.xml 整合

5.1 Maven Profile 与 Spring Profile 到底有什么区别？

维度 Maven Profile Spring Boot Profile
激活命令 mvn -Pprod package --spring.profiles.active=prod
执行时机 构建时 运行时
控制对象 依赖、插件、构建属性、资源过滤 配置数据、Bean 的环境化激活
是否需要重新打包 取决于构建内容；通常是 通常不用
是否自动互相联动 不会 不会

建议：同一份 JAR 在不同环境运行，环境差异通过 Spring Profile、外部配置、环境变量或 Secret 注入。Maven Profile 更适合控制构建元数据、测试策略、构建插件等。这样可以减少“测试用的包和生产用的包不是同一个包”的差异。

  2. 同一份 JAR 无法自然地在测试和生产之间迁移（虽然运行时仍可用更高优先级属性覆盖）。

7. 常见问题与排查方式

现象 常见原因 排查建议
修改 application.yml 不生效 被外部文件、Profile、环境变量或 CLI 覆盖 按属性源优先级从高往低查
application-prod.yml 不生效 未激活 prod 或路径不正确 检查启动参数及 Active Profiles
mvn -Pprod package 后没有进入生产环境 Maven Profile 不等于 Spring Profile 运行时显式指定 spring.profiles.active
@project.version@ 原样输出 Maven 没有过滤该资源 检查 Parent POM、resources、target/classes
${APP_NAME} 无法解析 没有设置环境变量、也没有默认值 设置环境变量或声明合理默认值
@Value 找不到配置项 Key 拼写、Bean 管理方式、配置加载时机有误 使用规范 Key，确认是 Spring Bean
配置属性类没有注册成 Bean 少了 @ConfigurationPropertiesScan / @EnableConfigurationProperties 检查扫描路径及注册方式
@PropertySource 无法加载 YAML 默认注解不支持 YAML 使用 Config Data 或自定义 PropertySourceFactory
明明只改一个 List 元素却整个 List 变了 List 是整体覆盖，不是拼接 在高优先级配置中提供完整列表
启动时报找不到配置位置 自定义配置路径不存在 检查绝对路径、工作目录和 optional:
spring.profiles.active 报无效属性 写在 Profile 专属文档内 移到基础非 Profile 文档或启动参数
